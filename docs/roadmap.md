# 渐进路线

Windows 原生能力的细化计划（事件订阅、语义位置、Shell、主题、语音、捕获策略、窗口组合与提供者学习路径）见 [Windows 窗口运行时路线图](windows-roadmap.md)。它记录的是候选规划，不代表已经实现。

## 阶段 0：本次原型源码

世界/窗口层级；单写租约与读快照；动态组件树；事件回执；托盘；内部管理器；外部 Python 提供者；默认只读外心桥接。源码交付后，本机已通过 Rust/Tauri release、真实 WS 验收探针与 TrafficMonitor x64 Lite 的实时只读 provider 链路；其余 Windows 人工验收单列在 `evidence/local/validation-matrix.md`。

## 阶段 1：同一条真实链路跑通

Rust core/server 与 Tauri release 已构建并通过对应测试；真实 lease probe 覆盖认证、单写/读者、动态 patch、过期、重连 fencing 与慢消费者；TrafficMonitor x64 Lite 经本地桥接进入 Tauri 原生世界。剩余点击穿透救援、人类/提供者几何、多屏/DPI、休眠恢复和 ACL 等人工/系统边界继续按验证矩阵推进。ExoMind RT 仍待用户实际地址与档案且当前由用户暂缓。

## 阶段 2：从一世界单写到多提供者组合

设计窗口 authority 与组件子树租约分离；父子撤销；共享布局边界；跨子树操作禁止/协商；动作路由跟随组件 owner；不可变快照读者继续独立。用同一世界里的外心计时和 Obsidian 统计验证，不能只拿两个随机构造器演示。

## 阶段 3：窗口行为成为可复用原语

先建立有类型的窗口事件订阅和受限响应；随后探索工作区锚定、贴边、有限动作轨迹、按上下文显隐和用户授权的应用聚焦请求。行为在宿主本地执行，提供者表达意图，不通过网络每帧搬坐标。附着外部应用、光标跟随和临时透镜继续作为更高权限候选，须先验证目标生命周期、焦点限制、多屏/DPI 与救援路径。

## 阶段 4：桌面生态与熟练提供者路径

逐步探索可选的任务栏/Alt+Tab 曝光、TrafficMonitor 风格任务栏摘要、宿主托盘通知、AppBar、主题预设与受限 token 定制、区域输入、语音会话和捕获策略。高权能项目默认关闭；先有 capability、授权、原生回执和回滚，再进入 Agent 示例与课程。

## 阶段 5：蓝图、窗口组与生态

蓝图保存结构与布局，业务状态仍由提供者重建。探索多个独立世界的临时组合；设计组生命周期与原子操作时仍保留每个世界各自的租约。长期授权与安全通道；受签名/受控的组件扩展；普通用户配方；性能调度。不能把当前不做长期绑定误写成“产品永远不允许持久化”。

## 验证引导演进

若第二个独立提供者仍需修改宿主业务代码，先修正抽象；若多写者主要争的是窗口几何，先分 authority；若瓶颈是 UI 布局，不先换传输；若用户只需要临时工具，不先做常驻仪表盘生态。
