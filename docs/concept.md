# 概念研发：窗口作为应用的自然延伸

最初需求不是再写一个计时器、硬件监控器或桌宠，而是让已有程序取得一个可以独立存在于桌面的交互部分。原应用继续计算、存储和裁决；宿主负责把声明变成可见、可操作、可定位的窗口。

## 两条同等重要的可编程能力

界面构造：组件、布局、数据绑定、交互。

窗口行为：位置、尺寸、层级、输入属性、显隐、生命周期。不能把后一条降为“画好卡片之后顺手置顶”。

## Minecraft 隐喻的有效部分

世界对应窗口实例，提供者对应参与者，组件对应方块，声明与数据对应构造指令，组件 catalog 对应可用方块集合，宿主对应运行这些世界的进程。加入世界不是只看一眼注册好的模板，而是可以持续搭建、重组和互动。

隐喻提供的是组合能力，不是视觉风格要求；原型不需要像素画面，也不意味着要先做游戏引擎。世界也不等于持久存档。蓝图与业务存档是后续可独立讨论的层次。

## Rust 隐喻的有效部分与限制

借鉴明确所有者、受控访问、生命周期与失效机制。远端会话不是 Rust 引用，网络也没有编译期借用检查。Rust 的 `&mut T` 不能与同一值的活跃共享引用随意共存；本项目的多个读者持有的是已发布的不可变快照，不是写入对象的实时内存别名。

本原型采取“独占写租约 + 快照订阅”，并用服务端会话/lease ID/epoch 检查网络消息。Rust 类型系统负责实现代码的内存安全，宿主协议负责远端权限，二者不可混淆。

## 关于‘身体的延伸’

用一个脚本发送 `scene.replace`，它获得表达；发送 `window.configure`，它获得空间姿态；接收 `interaction`，它获得局部感知；返回 `action.result` 与新数据，它完成反馈。

这些能力足以让应用在桌面中延伸，却不需要宿主成为应用的大脑。今后的桌宠路径，也应是提供者状态和渲染扩展的组合，而不是把饥饿、心情、任务规则塞进通用内核。
