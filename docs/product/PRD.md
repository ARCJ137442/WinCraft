# 产品范围与验收故事

## 一句话定位

面向自动化程序、兼容 Agent 的可组合桌面窗口运行时。它延伸已有程序，不替代其业务。

## 首批使用者

已有脚本或应用状态，希望获得桌面交互而不想重复开发原生 UI 的个人开发者与小团队。用户可以是提供者作者，也可以只使用预设；首版优先验证开发者接入链路，不声称已完成普通用户无代码编辑器。

## 故事 A：一个脚本加入空白世界

从托盘创建一个空白窗口；脚本取得真实宿主地址并握手；发现这个世界声明允许已鉴权提供者加入；取得独占写租约后发送组件树和数据。倒计时、进度和按钮出现。用户点击暂停，提供者确认后才显示暂停结果。

验收：调用者没有上传 HTML/JS；按钮事件到正确会话；连接中断后显示 stale 并禁用动作；窗口仍可通过托盘找回。

## 故事 B：进入之后继续搭建

同一脚本把进度条换成结果徽章，再插入日志/文本，再调整排列。界面不重启，已输入但尚未提交的文本不丢失。非法批次（例如先更新文字，再删除不存在的节点）应整批失败，不能只应用前半段。

验收：五种 scene.patch 操作有正反例；没有把‘新模板被忽略’当成常态功能；元素 ID 稳定保留输入状态。

## 故事 C：多个观察者，一个写入者

A 拥有窗口写租约；B 可受邀读取快照，但写入申请失败。A 释放之后 B 可以取得新的写租约。A 的旧消息即使随后到达，也不能修改窗口。

验收：两条真实 WebSocket 连接完成 probe；不是只在浏览器里模拟两个对象。

## 故事 D：人类与程序的窗口控制

提供者可以将 geometry_control 设为 provider，设置位置/尺寸；也可以明确交给 human。用户在 human 模式拖动后，宿主记录原生观测，不因下一次数据刷新把窗口拉回旧位置。

本地管理器的“接管并找回”是强制操作员动作：撤销写租约，解除穿透，恢复可见位置，并阻止提供者立即重新占用；解除接管后才可再次申请。不是偷偷把一个用户拖动事件解释成永久业务配置。

窗口内容默认允许选择文本；写者可通过 `window.configure` 切换窗口级默认，宿主组件样式可覆盖单个元素。公共标题栏始终不可选择。

## 故事 E：软件使用自己的能力

宿主平时只在托盘；打开管理器时，它以内部提供者身份构造设置、世界列表、接管和关闭按钮。按钮经过同一组件事件通道；不会出现第二套与通用组件无关的专用前端管理页面。

设置只在本次会话生效。确认关闭是两步操作；不把临时 UI 状态伪装成业务数据库。

## 故事 F：外心的真实只读投影

用户明确给出 RT 的实际端口和档案；桥接程序读取活动时间块，并将收到的字段投到世界中。RT 失败时，界面区分“桥接程序仍在线”和“外心来源已失败”；不自己继续演算出看似正确的计时。

本轮桥接只读，没有验证暂停/恢复的写链路。后续接入写动作必须针对独立测试档案且显式授权。

## 不用来证明首版成功的事

漂亮静态截图、仅一张模板卡片、网页模拟拖动、mock 租约测试、未运行的 Rust 测试源码、仅 debug 成功、仅构建安装包成功，都不足以证明原生产品闭环。
