# 界面与异常体验

## 视觉层级

世界的公共边框只负责名称、连接状态、拖动/关闭与诊断；组件区由提供者声明。使用低干扰深色背景、明确层级、少量强调色；不是强制最终品牌方案。

管理器与外部世界共用 renderer。管理器的“默认名称”“默认置顶”是实际可交互的内部提供者设置，不是单独写死的一页 HTML 表单。

## 状态语言

- vacant：等待提供者；不是错误。
- online：存在有效写租约；**仅说明连接/写入者在线，不说明外部业务采集一定新鲜**。
- stale：写入者离开/租约失效，保留最后显示但禁止业务动作。
- native.pending / applied / error / unavailable：窗口配置与操作系统之间的实际进度；不能以协议请求成功替代原生成功。

桥接来源需要在自己的数据中说明采集状态；外心只读桥接已经做了这个区分。以后可增加统一的数据新鲜度契约，不应现在伪称已支持。

## 输入与动作

按钮先进入 pending，收到 action.result 后显示确认或错误。结果不自动替提供者修改业务数据。输入框草稿、焦点和中文组合输入归宿主本地交互状态；数据刷新不能抹掉草稿。提供者投影回同一内容且动作确认后，草稿才视为提交。

旧 revision 上的点击可能被拒绝，避免把旧按钮的点击误解成新动作。首版精度偏保守；高频数据时可能出现可重试冲突，后续可拆分专门的交互语义版本。

窗口内容默认允许用户复制与选择文本。provider 可以配置窗口级默认；renderer 组件样式仍能针对特定内容覆盖。标题栏拖动区和控制按钮始终不可选择，避免文字选择影响窗口操作。

## 权限/恢复

穿透窗的按钮不能同时可点击。开启穿透后，用户从托盘找回。接管会明确撤销写租约并保持 operator hold，不让自动重连循环把窗口再次抢走。

关闭内部管理器只是隐藏它；关闭外部世界销毁该实例，不自动重开。提供者可明确再创建新世界，但不能继续向已销毁 ID 写入。

## 可访问性起点与欠账

已有语义化 button/input/label、键盘提交、focus-visible、进度 aria、状态 aria-live、减少动效偏好。尚未做完整屏幕阅读器和 Windows 高对比度验收，也没有声称符合某一级无障碍认证。
