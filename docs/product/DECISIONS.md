# 决定账本

日期：2026-10-31。本文区分用户已经决定、AI 本轮实施取舍和尚未实现，不把讨论过视为验证通过。

2026-10-26 的下一世代取舍、追踪账本与未验收项见 [平台演进交接包](../strategy/2026-10-26/START_HERE.md)。该包中的新契约仍是提案；决定账本的状态标签不会替代本仓库实现与验收证据。

## 用户已确认

| 决定 | 对实现的约束 |
|---|---|
| 世界就是窗口 | UUID 寻址一个窗口实例；不暗含永久存档 |
| 业务状态外置、运行状态可重建 | 宿主不维护外心计时/任务/笔记的另一份权威业务状态 |
| 全局 Harness 纵览单窗切换与渐进披露 | 一个悬浮世界聚合用户选定的来源/实例/会话；Claude Code 本地会话文件、Codex CLI 本机状态库、Codex App 本机状态文件是三种独立来源。Codex App/Claude Code 进程状态由本机进程证据决定，详情由各自有界磁盘读取提供；不依赖 live App/CLI connector。会话卡片显示名称、状态、项目与最近 Agent 输出；来源状态、磁盘可读性和新鲜度分开，完整日志和操作权限不默认披露 |
| 多读单写，先窗口再组件 | 首版整个世界只有一个活动写租约；其他会话只能看不可变快照 |
| 无固定绑定/常客 | 加入、租约、动作路由仅在内存中；断线即清理会话 |
| 宿主托盘化、管理界面自用 | 不需常驻主窗口；管理器是内部提供者生成的世界 |
| 调用者不用前端技术 | 外部只传声明、数据与事件回执；不上传脚本、网页源码 |
| 提供者包可由管理器拖入 | `.wcp` 配置蓝图与可执行 Provider bundle 是不同 manifest 类型；代码包拖入只预览，安装只解包，运行前必须逐次确认，绝不自动安装依赖 |
| 核心仓库的业务样例保持通用 | Obsidian 示例只呈现通用文件/工作区元数据与本地专注计时；业务专用仪表盘或插件对接细节留在其归属项目，不进入 WinCraft 公共文档 |
| Rust；最多 Tauri WebView | 不采用 Go/Electron，也不为每个提供者启动网页环境 |
| 连接后继续搭建 | 支持运行中增加、移除、替换、重排组件，不限第一次注册 |
| 窗口可交给人类，也可由程序控制 | 默认 human 几何模式允许用户调整窗口宽度与尺寸；provider 几何模式由提供者控制；本地管理器保留明确接管入口 |
| 工作区语义锚点 | provider 几何模式可声明当前显示器工作区四角与逻辑边距；宿主按显示器 DPI 换算并夹取窗口；human 模式拒绝锚点，本地 rescue 清除锚点并恢复 human 控制 |
| 悬浮窗按实际内容呈现 | 默认依据 renderer 实际布局高度安排原生窗口高度；宽度调整后保留用户宽度并按新布局重算高度；页面/窗口级滚动条默认隐藏，超出显示器可用高度时只在内容区内部保留滚动访问 |
| 仪表盘文本不应撑破窗口 | 长文本在组件可用宽度内自然换行；不能横向溢出或让布局反复震荡；内容变化后高度测量应收敛，长内容仍能访问 |
| 右键交互遵循显式注册 | 默认阻止 WebView 原生上下文菜单；仅静态注册 `context_action` 的交互组件响应右键，并把已注册动作交给当前提供者 |
| 隐藏与销毁是不同操作 | 标题栏最小化只隐藏窗口并保留世界/租约；关闭按钮可销毁普通世界；快照暴露 `visible`，provider 可用 `window.configure` 恢复显示，管理器也能重新呈现隐藏世界 |
| 悬浮窗默认置顶 | 新世界与世界管理器默认 `always_on_top=true`；提供者可用 `window.configure` 显式关闭或重新置顶。普通窗口不能盖住置顶窗口；另一个置顶窗口是否在前由 Windows z-order 决定 |
| 标题栏与指针穿透显式配置 | 标题栏默认显示且固定在可滚动工作区外；provider 可切换标题栏显示，click-through 默认关闭且 provider 可配置；隐藏标题栏后本地接管/找回入口仍可恢复 |
| 标题栏单击折叠内容 | 有标题栏时，单击标题区域且未发生拖动应折叠/展开下方内容；保持标题栏、世界和租约。拖动仍使用原生窗口移动；折叠是本地显示状态，不销毁或重建世界 |
| 托盘全局临时隐藏/显示 | 托盘提供“暂时隐藏全部窗口”和“显示全部窗口”；这是可撤销的宿主级可见性覆盖，不销毁世界、不撤销租约，不改各 provider 的单窗 `visible` 偏好；恢复时只显示当前仍逻辑可见的世界 |
| 健康连接状态降噪 | provider 世界正常 `online` 时不显示“已连接”状态行/徽标；启动、断开、过期、错误等异常状态仍显示 |
| Windows 虚拟桌面范围 | 每个窗口默认只出现在当前 Windows 虚拟桌面；provider 可请求“显示在所有桌面”，TrafficMonitor/外心悬浮工作台是开启示例。该决定已记录，但 Windows 公共 Tauri API 尚不能实现该 pinning，不能先提供假成功开关 |
| 悬浮工作面默认半透明 | 默认 `surface_opacity=0.8`，窗口保持原生透明背景；provider 可读取快照并用 `window.configure` 调整该值 |
| 模型额度悬浮窗 | 以图形化窗口并列呈现 Codex、MiniMax、DeepSeek 等额度；来源、币种、模型窗口与更新时间分开显示，不能把未知值当作零或混合不同周期 |
| 阻塞式提问窗可更不透明 | Popup-Ask 属于需要阅读和填写的临时窗口，可以采用高于被动 HUD 的不透明度；不改变其他窗口的 0.8 默认 |
| 窗口文本默认可选 | `text_selectable=true`；provider 可读写窗口级默认，组件样式可覆盖，标题栏始终不可选 |
| 国际化从早期进入 | host 自有静态文案提供 `zh-CN` 与 `en-US` key catalog；机器 ID 不翻译；provider 原始文本不自动翻译；内部管理器提供语言切换 |
| 受限主题与可信界面分离 | provider 可用有限 theme tokens 贴近来源软件；不接受 CSS/HTML/JS/远程资源；标题栏、来源身份、权限与接管区域由 host 控制；本机缩放、高对比与减少动画优先于 provider 主题 |
| 世界管理器超长内容 | 管理器固定窗口壳与工具栏，工作区在高度受限时内部滚动，滚动不改变世界或 provider 状态 |
| 不限本机提供者 | 协议身份不使用本机 PID 作安全依据；远程传输需有鉴权与保护 |
| 从外心悬浮工作台代码出发 | 固定源快照、保留许可证与迁移说明；不复制外心业务状态机 |
| 跨应用原生窗口操作由宿主提供 | 提供者只声明宿主登记的应用 ID、枚举操作与有界标题筛选；只有用户交互触发，宿主负责 OS API 与回执边界，不接受脚本、shell 或任意进程路径。当前注册 Obsidian/TrafficMonitor 的激活、最大化、恢复、最小化操作；宿主全局显隐由托盘本地负责 |
| 立即交付源码和文档给 Codex | 不再用新一轮需求问卷代替实施 |
| Popup-Ask 的结束、复现位置与键盘流程 | 成功提交销毁临时世界；后续提问复用上次可观察的原生位置/尺寸但创建新 world/lease；单选后 Tab 直接进入备注，Ctrl+Enter 连同当前备注草稿提交 |

## 本轮 AI 实施取舍（不是用户额外确认）

- 对外使用单一 WebSocket 双向数据通路；HTTP 仅用于 health/discovery。协议保留版本/能力握手，不假装实现了多通道动态升级。
- 默认 loopback 随机端口；安全隧道支持非本机提供者；不实现原生 TLS/LAN 监听。不是永久产品限制。
- 运行时 token 每个宿主随机生成；每个世界可为受邀或对已鉴权会话开放。
- 写权限是 15 秒可续租的运行时租约。每次更替有 epoch；它不是 Rust 编译器跨进程借用。
- 默认窗口几何交给人类。提供者主动切换到 provider 模式后才可设置位置/尺寸；人类接管会撤销租约并设置 operator hold，直到本地解除。
- 宿主暂存输入草稿、IME 组合、操作等待状态、窗口几何与组件树，不保存业务数据库。
- 首批 10 个组件；前端采用无框架 TypeScript，而非搬入整个外心 React 应用。Tauri 原生窗口与外心窗口模式保留。
- 限制 16 个世界（包含内部管理器）、每世界 256 节点/深度 16、单消息 256 KiB，以便先验证完整链路。
- 管理器为进程内可信提供者，与外部同用 Engine/Scene/事件语义；它有明确的本地操作员权限，不要求绕本机 WebSocket 自发 HTTP。
- Agent Activity 总览最多预览两条 Codex CLI、两条 Codex App、三条 Claude Code 会话；Codex CLI 只读取最近四个线程的 `agentMessage`。Codex App 从本机只读 state DB 的 `Codex Desktop` originator 读取标题/项目，并只解析经过 session meta 匹配的有限 rollout 尾部；Claude Code 从项目 JSONL 与固定子 Agent 路径读取本机历史。两者用 OS 进程映像状态区分在线/离线，进程离线仍可浏览历史；没有权威逐会话状态时显示 unknown。来源不给出或不能唯一匹配输出时明确显示不可用，不从用户提示或工具结果推断。
- Popup-Ask provider 按上述可读性要求把自身窗口默认不透明度设为 `0.92`；这是本轮实施值，其他窗口仍按全局默认 `0.8` 或各自 provider 配置。
- Codex 额度暂用本机显式启用的实验适配器：有界解析 `auth.json` 到本机进程内存，但只使用必要字段并忽略其余内容；请求固定的 HTTPS GET。该后端路由不是稳定公开 API，默认不启用，不刷新/写回凭据，不记录令牌或账户 ID。TeamSense 仍只用受 `data:read` 保护的缓存 GET；两者身份与新鲜度分别呈现。
- 协议接受表示权威模型已更新，不保证 OS 已应用；native report 单独说明成功/失败。
