# 执行摘要：让程序长出界面，而不是让宿主长成业务大全

## 已确定的方向

WinCraft 是人、程序与 Agent 可以同台参与的可组合界面运行时。Windows 悬浮窗是首个承载，不是哲学边界；当前“世界”仍与一个窗口实例对应，后续可增加交互会话、组件和资源域，但不为名词升级重写当前 ID 或生命周期。

主线是稳定可拓展内核、公共 API、可信声明式渲染、原生能力、发现与组合。提供者持有业务真相；运行时维护可重建投影、授权、租约和局部交互。成功不是“接口比 Win32 多”，而是借用窗口、控件、发现、输入、版本与恢复无需各自重造。

## 用户最新反馈对旧建议的修订

| 旧建议中容易扩大的部分 | 本包的约束 |
|---|---|
| 整合包打包预设软件 | 整合包保存配置、能力需求与适配方案；不承诺封存、安装或复现提供者 |
| 官方先建设扩展市场 | 先有开放格式、文档、示例与可分享作品；社区聚合由真实使用生长 |
| 桌宠作为产品功能 | 只验证表达/运动扩展点；不做宠物业务、角色养成或 Live2D 平台 |
| 所有功能都插件化/修改宿主 | 普通接入只走 API；Mod 和任意宿主代码加载暂缓 |
| 中文名“窗构”作为确定品牌 | WinCraft 为研发名，WinC 可作简称；中文名暂不冻结，不改技术命名 |
| 用户确认等于功能完成 | 批准的是方向；具体契约、实现与验证分别记录状态 |

## 第一个纵向成果

先使现有 `popup-ask` 的外部调用与返回保持兼容，增加 WinCraft 呈现 transport：创建临时世界 → 人类选项/备注 → 结构化返回 → 清理世界。保留关闭即取消、恒定 Other/notes、用户语言、默认摘要与显式 JSON。等待人类的时间不能误用宿主当前 10 秒 action ack 超时。完整设计见 [一次性交互](docs/09_EPHEMERAL_POPUP_SYSTORCH.md)。

SysTorch 的“发起任务”和“做出决策”是同一通用交互能力的两种提供者业务，不进入内核。实际 SysTorch API 未在本轮定位，先给端口契约与合成 fixture，不能接入同名第三方项目冒充。

## 四条贯穿所有批次的工作

**可靠性**：版本协商、取消、租约隔离、结果语义、资源回收和本地接管。

**国际化与主题**：可读文案从第一批开始分离；主题可像来源应用，但来源身份和授权条不能被主题掩盖。

**时效与证据**：文档带更新时间、验证基线、适用版本和状态；老证据不自动继承，英中译文能检测漂移。

**开放但有限的生态接口**：格式与 SDK 稳定，配置包可适配当前环境；不把公网、任意执行和第三方信任变成默认值。
