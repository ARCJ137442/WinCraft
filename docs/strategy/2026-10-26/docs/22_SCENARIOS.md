# 串起来的用户叙事：从个人工具到可组合环境

以下为设计情境，不是访谈结果、现有功能或实机验收记录。每段对应路线任务，业务示例都是合成内容。

## 1. 问题终于出现在需要它的人面前

你让一个编程 Agent 修复数据迁移，自己切到资料窗口。它遇到两条同样合理的路径，以前只能在终端等你发现。新的 popup transport 让它申请一个临时世界，展示“保留旧配置”与“迁移新格式”的后果，并保留 Other 和备注。你写下一句中文边界，提交后旧调用方收到同样的结果，窗口退出。

第二次你直接关闭窗口。Agent 得到 cancelled 而不是替你选择第一项。它不开始执行依赖未决答案的迁移。真正新增的不是一张卡片，而是可靠的“提问—等待—回答—退出”连接。对应 B03。

## 2. 同一张桌面，发起与裁决都有自己的入口

你用 SysTorch 的启动世界选择一个工作目标。它根据原系统规则创建任务，而不是窗口自己假装开始。稍后任务遇到决策点，另一个风格一致的世界呈现证据和分支。两次看起来都像 SysTorch 自己的 UI，却分别代表人类调用与人类裁决；来源标识与权限仍由可信区域保护。对应 B03/B02。

## 3. 网页状态来到桌面，但登录没有被偷渡

你打开 TeamSense 查看服务器负载，随后在 IDE 中工作。扩展把你明确选定的三个指标投到桌面，额度旁边显示统计窗口和更新时间，而不是一个来历不明的百分比。网页改版后 adapter 失败，卡片显示来源失效；它不会把旧额度当实时，也不会把浏览器 Cookie 复制到 WinCraft。对应 B05。

## 4. 整合包遇到另一台电脑

朋友分享一套“开发工作室”。你的机器没有他的监控工具，却有两个编程 Harness。导入界面列出可用能力、缺失监控项和可替代来源；没有偷偷安装任何软件。你确认后得到适合本机的布局。第二天一个来源退出，区域明确变灰；重新加入后重新授权。整合包保留的是搭建方法，不是朋友的设备。对应 B06。

## 5. 五种 Agent 不再把桌面切成五份

两项任务正在运行，一项等待你的输入。你以前逐个看终端，现在各来源在自己的区域更新。一个 adapter 重启后显示同名任务，但实例 ID 已改变；旧批准按钮失效。你能比较状态，却不能因为统一界面就绕过每个 Harness 的策略。对应 B07/B08。

## 6. 手机摘要与电脑待办并排而不互相夺权

手机将被允许应用的通知整理为一条摘要，通过用户选择的通道送到 PC。面板旁边同时显示三个等待输入的开发会话。你点击摘要只会回到对应内容或发起明确动作，不会自动回复联系人的消息；手机暂时离线，更新时间让你知道这不是实时镜像。对应 B09。

## 7. TouchAI 作者不再先画一整套窗口

协作者保留 TouchAI 的模型、上下文和工具逻辑，把查询与结果通过适配器呈现。热键已被占用时系统允许改绑，而不是失去整个入口。主题很像原应用，但权限提示不受主题控制。界面等价与业务等价逐项验收，没有因为输入框出现就宣告迁移完成。对应 B04/B05。

## 8. 一款 APP 先从一个世界长出来

PCSense 作者先做个人任务和设备状态的窄面板，发现哪些信息值得常驻、哪些应该只在请求时出现。几轮后他决定独立成 APP；导出的蓝图、文案和业务 Provider 可继续使用，秘密与 lease 没有一起带走。WinCraft 完成了孵化职责，不要求作者永远留在平台。对应 B10。

## 9. 角色不是新的业务后端

一个虚拟形象根据来源状态切换姿态。来源失联时它清楚显示离线，不能继续表演任务进展；用户减少动画时它安静下来。其角色素材与业务逻辑由社区维护，平台只证明呈现、动作、输入和退出能力。对应 B10。
