# 下一步路线图：分批形成真实闭环

## 总原则

方向已获用户通过，工程默认由本包提出并可通过证据修订。不重复组织命名大会或功能问卷。先比较当前 dev 是否已有功能，禁止把已完成项再做一次。任务的唯一机器来源为 `plan/tasks.json`，本页只定义批次门。[U-LATEST]

| 批次 | 解除的限制 | 退出门 |
|---|---|---|
| B00 基线与治理 | 文档/源码/证据可能漂移 | 本地 HEAD、旧链路回归、规则落盘、未测项分层 |
| B01 契约与生命周期 | 扩展容易破坏已有 Provider | 0.3 兼容路线、能力查询、资源清理/发现最小契约 |
| B02 i18n/主题/教程 | 原型只对作者可用 | 中英、可信主题、教程/管理器自用 |
| B03 临时交互 | 提问仍依赖专用窗口 | Popup 契约兼容、成功/取消/断线、提交后销毁与位置复用、Tab/方向键/Ctrl+Enter闭环，SysTorch 端口 |
| B04 事件/快捷键 | 窗口只能被更新不能受控反应 | 类型事件、背压与因果、授权热键、TouchAI 窄用例 |
| B05 浏览器/在线服务 | 网页状态留在浏览器 | 受控桥接、TeamSense 只读；聊天/语音独立门 |
| B06 自适应配置包 | 分享配置依赖同一台机器 | 有/无来源规划、预览、导入回退、无秘密导出 |
| B07 细粒度所有权 | 一窗只能一个写者 | 子树/数据隔离、父子撤销、并发不相交写 |
| B08 多 Harness | 状态与待办分散 | 两种真实 Harness 先验，再扩五种；审批单独授权 |
| B09 设备摘要 | 手机与电脑信息分裂 | 中立消息信封、单真机/单通道、乱序去重与撤销 |
| B10 孵化与可能性 | 创作者需先做完整 APP | PCSense 窄原型、导出毕业路径、角色最小扩展 POC |
| B11 平台与公开发布 | 只能作者本机用 | Windows release 验收、性能/兼容与发布材料，其他 OS 分开 |

## 关键依赖

```text
B00 → B01 → B02 → B03
          ├→ B04 → B05
          ├→ B06
          └→ B07 → B08 → B09
B02 + B06 + B07 → B10
每一批证据 → B11 发布门
```

依赖图是便于理解的概要；任务 JSON 的 `depends_on` 才是执行依据。B08 可先以聚合 Provider 独占窗口做只读演示，但“各 Harness 自己写子区域”必须等待 B07。B09 的模拟信封无需等真实 BLE/USB 网络；真实 transport 由另一项目提供。

公开发布门针对当次选择的已实现能力，不要求先完成PCSense、Android或全部Harness；未交付能力明确排除，不能用总路线阻塞一个已验收的小版本。

## 第一轮建议实际完成到哪里

完成 B00 的差异审计与规则、B01 最小兼容决定、B02 中英/主题骨架，以及 B03 Popup 一个真实闭环。不要为这个闭环先上共享 Mutex、市场或全套浏览器适配。预算不足时以最小可用纵向结果结束，记录未完任务，不宣布完整路线已实现。

## 停止与反转条件

如果每个 Provider 仍需改宿主，修抽象而非继续加专用分支；如果数据更新导致不相关写者冲突，先做局部 revision；如果语言/主题注入绕过可信授权，先停相关能力；如果现有 0.3 回归失败，恢复兼容再推进。

对真实第三方 API 无来源或无授权时，阻塞该 adapter，不阻塞模拟契约、核心或文档工作。对多平台无测试机器时，保留 NOT_RUN，不压成一个“跨平台已支持”标签。
