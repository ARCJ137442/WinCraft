# 治理、许可、品牌与发布

## 已冻结的方向

本阶段保持现有 CCOPL-1.0 与上游来源说明，不重新争论、更换或擅自增设许可。后续集体维护与许可细化由外心团队决定。用户提及星林与 ARCJ137442 参与是治理意向，不意味着本包已经授予仓库权限、创建组织或签署协议。

WinCraft 为研发名，WinC 可作为交流简称；“窗构”可留临时标签或去掉，中文正式名不冻结。不强制本地代理为新名称重命名 crate、protocol、路径和历史记录。公开介绍可坦率说明借鉴 Minecraft 的世界/方块/参与者隐喻；不复用其美术素材、字体、标志或制造官方关联。

## 授权边界

本包交付文档、契约和计划；未修改远程仓库。Luna 收到执行提示后可按用户授意在现有仓库本地整合、开发、测试；提交/推送/发版/安装真实插件/配置手机通知需分别核对当前授权。不要把“全部方向通过”扩大为公开私有文件或修改账户的许可。

## 维护建议

采用角色而非擅自指定个人：产品/协议负责人、内核评审、原生验收、文档/i18n、Provider 维护者。涉及 lease/授权/IPC 的变更必须有独立审阅或显式记录未做独立审阅，不能自称双重审核。

社区先用 GitHub topic、统一 manifest、示例和中英文档降低分享成本。不先建设账号、支付、评分和市场运营；后续社区自发 awesome 聚合是观察指标，不是先由官方造出来再声称生态形成。

## 发布准备

Windows stable/preview 分开，独立 release 校验、哈希、签名/未签名状态、权限说明、升级回退、已知限制、兼容表和隐私说明。macOS/Linux 单独构建和验收，能力差异明确；不能因 Tauri 的平台列表而把所有能力勾绿。

源码公开与制品发布是不同动作。Release 文案引用已执行矩阵，不复用上一版测试结论。避免携带 descriptor、业务数据、用户路径和私人日志。

## 资料公开规则

公开的产品/架构/协议草案可以整合；团队技能的受限摘要只写必要契约，不复制其全文。`sources/registry.json` 中 visibility=restricted 的项目在公开提交前需脱敏/删去内部定位，保留可追溯的本地记录。本包不发布任何第三方源码副本，引用不是重新授权。
