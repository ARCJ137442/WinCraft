# 安全与信任：用户可理解、内核可执行

## 三种信任层

**声明式配置**：校验过的组件、主题、包、引用；本身不能执行代码，但仍可能携带恶意内容/资源/权限诱导。

**外部 Provider / 适配程序**：独立运行，拥有其进程权限；宿主协议限制它能影响的世界，不声称限制了它全部 OS 能力。

**宿主扩展代码/Mod**：当前不开放；今后若开放必须重新设计执行隔离、来源和权限。不能把这一项伪装成配置包的小功能。

Obsidian Restricted Mode 可参考为第三方启用交互，但官方说明插件继承应用权限，不能可靠限制到特定能力；WinCraft 的授权必须由实际路由检查，不靠一个“安全模式”标签。[OBS-SEC]

## 授权模型

请求声明不等于授权。grant 绑定 Provider 身份/实例、资源、操作、上下文、期限；本机用户授予、撤销。启动状态只有最低权能；快捷键、麦克风、外部窗口观察、捕获策略、通知、网络发现独立申请。

主题与 Provider 内容不能画出能冒充宿主的许可按钮；原生/可信区域显示身份和后果。本机 operator 不能通过普通网络消息请求，保持 caller-bound IPC。

## 首要威胁与控制

| 威胁 | 控制与验收 |
|---|---|
| 包内路径穿越/符号链接/资源炸弹 | 限额、类型校验、解包路径根约束，不执行安装 hook |
| 适配程序伪装成纯配置 | manifest 标明执行性、哈希与授权；默认不运行 |
| Prompt injection 来自网页/通知 | 文本作为不可信数据，不改变命令、权限或批准 |
| 跨 Provider 数据窃取 | 服务器按 read scope 过滤快照，不能先全发再隐藏 |
| 权限撤销后旧消息继续写 | epoch、资源世代、租期、旧会话拒绝 |
| 宿主 token 被网页取得 | Native Messaging bridge 保管，不放宽 Origin |
| 用户界面主题冒充授权 | 可信 chrome 不可覆盖，来源标签不可伪造 |
| 远程摘要重复/重放 | 来源认证、message_id、source_seq、TTL 和撤销 |
| 无限弹窗/声音/热键 | 世界与事件配额、注意力预算、用户一键停用 |
| 共享锁阻塞所有 UI | 有界 CAS/仲裁、不持锁 await/等人、超时与取消 |

## 证据和公开

全部默认使用 synthetic fixture。真实账户、手机通知、浏览器会话或外心写 API 只能按用户独立授权范围进行；本包总体验收许可不等于读取所有私有数据。日志保留必要 ID、结果、时间和版本，避免正文。签名/哈希只能说明来源/完整性，不证明安全。

发布前复核 privacy、权限、依赖审计和离线恢复；不得标注“已安全认证”。当前回环＋token 仍是受信任机器原型，不直接作为公共多租户服务。
