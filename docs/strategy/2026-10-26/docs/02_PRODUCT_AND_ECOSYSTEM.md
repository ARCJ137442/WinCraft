# 生态定位、边界与成功指标

## 参与者与平台提供物

| 参与者 | 主要产物 | 平台承诺 |
|---|---|---|
| 应用/自动化作者 | Provider、适配器 | SDK、能力查询、状态与交互、版本兼容 |
| 人类创作者 | 蓝图、主题、配置配方 | 可读格式、验证器、预览和安全导入 |
| Agent | 按同一协议运行的 Provider | Skill、结构化错误、发现与示例；没有隐藏高权接口 |
| 整合作者 | 环境需求与自适应配置 | 有什么用什么；缺失来源可解释地降级 |
| 普通用户 | 选择与轻修改 | 教程世界、设置世界、撤销和恢复 |

## 不做与保留接口

不做第一方插件市场、账号体系、评分支付与推荐系统；可在现有仓库以 topic、示例目录、开放 manifest 和英文文档支持社区自发 awesome 清单。不能把官方主动做的聚合页计作社区自发生态证明。

Live2D 仅是“创作素材/作者/整合/使用者能够互相成就”的参照。运行时不默认捆绑其 SDK、模型、授权或商店；角色业务留给提供者。

PCSense 是应用孵化试验：在公共 API 上验证个人电脑运营界面，再按实际需求独立为 APP。退出平台或独立部署应可行；“毕业”不是项目失败。

## 为什么选 WinCraft 而不是直接调用 OS API

直接 Win32 的自由度可以更大，但调用者还需承担窗口生命周期、组件、事件、输入法、主题、可访问性、会话隔离与发布维护。WinCraft 面向想参与同一创造环境的人/程序/Agent，交换一部分底层自由度以获得公共机制与协作成本优势。这是价值主张，不是性能或功能覆盖率的绝对比较。

## 观察指标与计量边界

先量首次接入所需修改、能否不改内核接入第二来源、旧 Provider 的升级存活、取消正确率、资源回收与“配置迁到另一台机器后还剩多少手工工作”。再观察独立作者、跨作者配方复用、社区自发文档/聚合。

不编造增长目标、市场规模、性能目标。可记录 `time_to_first_interactive_world` 和作者卡点，但未经同意不遥测真实笔记、消息或会话。设置可关闭统计；默认开发测量用合成数据。
