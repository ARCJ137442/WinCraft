# 产品哲学与章程

## 本质：把系统可行性转化成可借用的创造能力

直接调用 Windows API 并不等于得到一个可共享、可组合、可找回、可国际化的工作环境。WinCraft 提供的不是更大的底层权限，而是更低的接入成本与更清楚的协作规则。它把组件、交互、窗口行为、发现、授权和生命周期组织成一个运行时。[U-LATEST]

Minecraft 是组合性、渐进学习和多人参与的模型隐喻，不是依赖管理实现模板，也不是视觉素材来源。用户所谓“不需要自己不断加内容”在工程上落实为：业务多样性由提供者承担，平台持续维护能力、兼容、性能、文档和可靠性；不能理解成可以停止维护核心。

## 产品承诺

**让已有程序通过声明式协议获得可搭建、可交互、可操控的桌面界面，而不必各自重新开发完整桌面应用。**

原生指真实 OS 窗口及系统集成，不暗示所有控件都是 Win32 原生控件；目前渲染是可信 WebView。低门槛指调用方不需要 HTML/JS 工程，不是零配置、零适配或零权限成本。

## 九条不可变原则

1. 人类保有本机撤销、接管、关闭与恢复权。
2. 业务真相留在来源；UI、连接和授权状态可以重建。
3. 创造通过公共契约发生；官方工具尽可能用同一契约自用。
4. 窗口内部表达与窗口本身行为同等可编程。
5. 发现不是授权，主题不是身份，收到不是完成。
6. 同一资源默认单写；读者消费不可变快照，不能借“共享”越权。
7. 实现承担边界条件；规划、静态代码、模拟与实机证据分开。
8. 生态先开放格式与接入，不先建设商业市场或任意宿主 Mod。
9. 持续保证第二个作者容易参与，不靠无限增加平台专用业务。

## 面向普通人的表达

世界是一块你能掌控的交互空间，当前由一个窗口承载。程序像参与者一样加入，放入方块并响应操作。你可以让它自己安排位置，也可以拿回控制权。别人分享的存档描述“怎么搭”，不是把他的账户、手机和程序都塞进你的电脑。

## 架构解释

Core 裁决资源与版本；API 组织协商和事件；Renderer 兑现组件；Native adapter 兑现系统意图；Provider 裁决业务；Pack resolver 提出配置计划。没有任何一层可以因“统一”之名夺走其他层的权威。

## “只做可能性”的可执行解释

不开发宠物养成、ERP 业务、通用聊天网站替代品或手机传输栈；但每个对外承诺的扩展点必须通过最小可行性 POC 和失败恢复验收。否则只是文档上的可能性，不是可依赖的平台能力。第一方示例只为证明原语，不成长为平台必须维护的垂直业务套件。
