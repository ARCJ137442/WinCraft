# 自用（dogfooding）管理器

`crates/wincraft-server/src/self_provider.rs` 是真正的内部提供者：注册服务端会话、创建受保护 system world、取得独占写租约、用 Node/Scene 构造界面、通过普通 action 事件收取按钮和输入、返回回执。

它没有自己的 React/HTML 专页。所有文字、设置输入、按钮、列表都交给相同 renderer。只有公共窗口外壳（拖动/关闭/连接提示）属于宿主。

## 为什么不强迫它经过本机网络

自用验证的关键是复用能力和契约，不是多做一次 TCP。管理器通过进程内 Hub.dispatch 调用普通请求路径，继续服从 scene 校验和 lease/revision 规则。操作员特权属于明确本地路径，不是伪造外部提供者。

## 实际设置与管理动作

本次会话的新世界名称、默认置顶；创建空白世界；刷新；展示世界状态与 native 错误；接管并找回；解除接管；两步确认关闭。`0.4-preview.1` 另提供本机 `.wcp` 配置包预览、来源/权限选择、显式 grant 后重新规划、确认后逐窗创建和两步回退；它仍是草案扩展，不进入稳定 0.3 外部方法表。管理器将 pack 的描述性 scene 用通用 renderer 显示，不加载独立 HTML 页面或运行 pack adapter。

托盘还保留救援和退出。不能完全依赖 renderer 来解救失效 renderer。管理器关闭时只隐藏，宿主继续存在；软件正常运行不要求一个主页面长期打开。

正常启动默认只显示托盘。开发/联调时可对桌面 EXE 传入 `--open-manager`，显式打开该实例的管理器窗口；不带参数的实例仍保持托盘优先。

## 边界

只管理 WinCraft 自己的世界，不是已经实现 AHK Window Spy 对所有外部程序的句柄探查。外部窗口探查与附着后续实现时，要区分只读信息、操控权限和用户明确选择目标。

管理器用于展示所有受管世界元数据，这是一种本地操作员权限；普通外部会话只能获得其成员资格允许的内容。系统世界本身不接受外部加入。
